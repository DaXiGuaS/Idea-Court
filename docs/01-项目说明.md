# 想法法庭 · Idea Court

一个可以「把你的想法扔进去、被五个角色轮番质疑、还能当场还嘴」的 AI 应用。

你说一个想法，一个 AI 分饰五位评审，从各自唯一的角度挑问题；你可以逐条反驳，票数会重新统计，最后给你一份带表决结果的判决书。

**项目定位**：笔试题作品，用于展示 AI 应用开发与内容表达能力。追求「打开就能玩、截图能传播、逻辑讲得清」，不追求高并发与生产级可用性。

---

## 一、它和普通的「AI 角色扮演」有什么不一样

普通做法是一句提示词让模型扮演多个角色：

```
你现在是 5 个不同的人，分别评价我的想法。
```

结果是五段话长得几乎一样——都在说「这个想法不错，但建议考虑 XX」。

本项目的差别在于三件事：

| 普通角色扮演 | 本项目 |
|---|---|
| 角色自由发挥 | 每个角色绑定**唯一审视维度**，并明确禁止越界 |
| 模型自己说「我投反对」 | 投票结果由**程序统计**，模型只负责表态 |
| 说完就结束 | 用户可以反驳，携带历史重新评审，票数会变 |
| 判决永远是「还需要完善」 | 三档结论：通过 / 有条件通过 / 驳回 |

对比示例（同一个想法「帮大学生整理课程通知的小程序」）：

| 角色 | 普通角色扮演会说的话 | 本项目实际输出 |
|---|---|---|
| 产品经理 | 建议明确目标用户 | 谁会用？大学生现在不都靠班群 @ 全体成员吗？ |
| 后端 | 需要考虑数据存储 | 通知数据从哪来？一个个学校对接教务系统？ |
| 测试 | 需要覆盖异常场景 | 通知里混着兼职广告，你怎么分？断网了呢？ |
| 老板 | 需要考虑商业模式 | 学生连视频会员都要借，谁付钱？ |
| 用户 | 需要提升用户体验 | 班群置顶一下不就完了？ |

差别不在「模型聪明不聪明」，而在**约束有没有写死**。

## 二、核心功能

### 两种评审模式

- **做产品**：产品经理 / 后端工程师 / 测试工程师 / 老板 / 真实用户
- **做个决定**：精算师 / 风险官 / 情绪观察员 / 过来人 / 反方

两种模式的角色、提示词措辞、判决话术全部独立配置，不是换了个标题。

| | 做产品 | 做个决定 |
|---|---|---|
| 场景描述 | 想法评审会 | 决定审议会 |
| 用户输入标签 | 提想法的人说 | 他正在纠结的决定 |
| 核心问题标签 | 最致命的问题 | 最该想清楚的问题 |
| 判决话术 | 通过 / 驳回 / 有条件通过 | 可以这么做 / 别冲动 / 再想想 |

### 多轮反驳

判决书下方有输入框。用户的反驳会作为一条发言插入时间线，五个角色基于历史继续追问，票数重新统计。

反驳框上方会列出**本轮五条发言各自的核心问题**，让用户知道该回答什么——这是降低「不知道怎么写反驳」门槛的关键设计。

### 判决书

- 票数由程序统计（`graph.py` 的 `build_verdict`），不让模型自己数
- 三档结论按票数规则计算：赞成 ≥ 3 → 通过；反对 ≥ 3 → 驳回；其余 → 有条件通过
- 输出「最该想清楚的那个问题」，且要求它必须来自本场发言，不能新编

### 分享卡

前端用原生 Canvas 绘制 750×1000 的竖版卡片（2 倍分辨率），包含标题、判决印章、想法、核心问题、票数，一键下载 PNG。不引入任何前端库。

### 预置案例与本地记忆

- 每个模式配 3 个预置案例，点一下直接开庭，解决「第一次打开不知道输入什么」
- `localStorage` 记住你之前提过的想法，下次某个角色会顺口损一句「上次那个也没做成吧」

## 三、技术栈

### 后端
- Python 3.13 + FastAPI + uvicorn
- LangGraph（评审 → 判决的流程编排）
- Pydantic（约束 LLM 输出结构）
- pydantic-settings（配置读取）

### 模型
- DeepSeek API（OpenAI 兼容接口）
- **JSON mode**（`response_format={"type": "json_object"}`）而非 function calling
- 温度 0.4

### 前端
- 原生 HTML / CSS / JavaScript，无构建、无 npm
- Canvas 2D 生成分享卡
- `localStorage` 存本地记忆

### 其他
- 无数据库、无 Docker、无 Redis
- 所有数据在进程内或浏览器本地，重启即清空

## 四、架构说明

分四层，从下往上：

### ① 配置与模型层（`config.py` + `reviewer.py`）

`config.py` 用 pydantic-settings 从 `.env` 读取 API Key、地址、模型名、超时。

`reviewer.py` 负责一次完整的评审调用：

1. 拼 system prompt（角色设定 + 铁律）
2. 拼 user prompt（想法 + 历史 + 反驳）
3. 调 DeepSeek，拿回 JSON
4. 用 Pydantic 校验结构，失败则重试（最多 2 次）
5. 轮次由程序赋值，不信任模型自己填

### ② 编排层（`graph.py`）

`StateGraph` 只有两个节点：

```
START → review（五个角色发言）→ verdict（统计票数、生成判决）→ END
```

刻意保持简单。用 LangGraph 不是为了炫技，是因为流程状态（想法、历史、反驳、结果、判决）显式声明后，谁产出什么、下一步读什么一目了然。

### ③ 数据模型层（`models.py`）

定义 `Speech` / `ReviewResult` / `ReviewRequest` / `Verdict` / `ReviewResponse`。

`vote` 字段用 `Literal["approve", "reject", "conditional"]` 锁死，模型输出别的值会直接校验失败。

### ④ Web 与前端层（`main.py` + `static/index.html`）

`main.py` 只做两件事：接收请求、透传给编排层；异常统一转 502。

前端是单文件，逐条渲染发言（打字机效果）、渲染判决书、处理反驳、生成分享卡。

## 五、本地启动

### 前置条件

- Python 3.10 以上（开发环境为 3.13）
- 一个可用的 DeepSeek API Key

### 启动

```bash
cd idea-court
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
cp .env.example .env          # 填入 DEEPSEEK_API_KEY
uvicorn main:app --reload
```

Windows 用户可以直接双击项目根目录的 `run.bat`。

浏览器打开 <http://127.0.0.1:8000>

### `.env` 说明

```ini
DEEPSEEK_API_KEY=你的key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
LLM_TIMEOUT=60
```

`DEEPSEEK_MODEL` 和 `DEEPSEEK_BASE_URL` 以你实际使用的服务商为准。

### 常见问题

1. **端口被占用**：`address already in use`，说明已有一个实例在跑，先结束进程或换端口 `--port 8001`
2. **接口返回 502**：看终端日志，多半是 API Key 无效或网络不通
3. **没有 `venv`**：`run.bat` 会提示先创建虚拟环境

## 六、测试示例

### 示例一：必被全票否决

**输入**：`一个帮大学生自动整理课程通知的小程序`

**预期**：5 票反对，判决「驳回」。

能体现「五个维度真的分开」：产品经理问使用习惯，后端问数据来源，测试问异常分类，老板问付费意愿，用户问凭什么多装一个。

### 示例二：能审「要不要买」

切到「做个决定」，输入：

```
我想花两万块买一台全画幅相机，主要用来拍旅行和日常，一年大概出去两三次
```

**预期**：判决「别冲动」。

能体现第二套角色的独立性：精算师算镜头和摊薄成本，风险官问摔了谁修，情绪观察员识破种草，过来人讲自己吃灰的经历，反方直接说「手机够了」。

### 示例三：反驳后翻盘

**输入**：

```
一个帮自由职业者整理收支的工具：从微信、支付宝导出的账单里自动抓取收支，按规则分类，每月生成一份可以直接给会计的报表
```

**第一轮**：0 支持 / 5 反对，驳回。

**反驳**（覆盖五个维度）：

```
目标用户就是自由职业者自己，自己付钱自己用。他们每月对着几百条流水手动分类要两小时，这个十分钟。
账单是微信、支付宝官方导出的 CSV，格式变了有适配层，一个月最多改一次；解析在本地完成，断网也能用。
退款、外币这些情况，规则里可以单独标记，分错了能一键改。年费 199，请会计做同样的事要两千。
获客从自由职业者社群里一个个聊，前一百个我亲自服务。不用装 App，微信小程序打开就用。
```

**第二轮**：0 支持 / 2 反对 / 3 有条件，判决「有条件通过」。

能体现「反驳真的会改变票数」，且改票不是无条件的——两个角色仍然反对。
